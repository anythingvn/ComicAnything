*Found during this verification pass (new, not from either prior fix round):* **(1)** *Resume-scroll-on-reopen does not work — confirmed via the raw DataStore file that `progressPercentage` is correctly written to disk (matched by hash to the test book's path), and `isFavorite` correctly round-trips through the same merge-on-load code path, but reopening the same EPUB (via direct tap, via search, and via a full cold app restart — three separate reproductions) always lands back at the very top instead of the persisted position. `isFavorite` merging fine while `progressPercentage`-driven scroll restore doesn't isolates the bug to `EpubReaderScreen.kt`'s `onPageFinished`/`view.scrollTo` resume logic rather than the ViewModel/persistence layer; likely `view.contentHeight` not yet reflecting final layout height at the moment the resume-scroll runs, silently making `maxScroll <= 0` and skipping the restore. This directly contradicts Step 5's requirement and is the most significant finding of this pass.* **(2)** *The Library/Continue Reading carousel never surfaces an EPUB, and would show a fabricated "Page X/Y" if it did — `HomeScreen.kt:290`'s `comics.filter { it.currentPage > 1 }` and the hardcoded `"Page ${comic.currentPage}/${comic.totalPages}"` label at `HomeScreen.kt:353` both assume the page-based progress model; EPUB's `currentPage`/`totalPages` are deliberately left at their default (`1`) per this epic's own design, so the filter never matches and an EPUB's real `progressPercentage` is never shown anywhere in the library UI.* **(3)** *The quick-settings theme row (`EpubReaderScreen.kt` around line 194) has no horizontal scroll or wrap, and 5 `FilterChip`s overflow the screen width on this device — `HIGH_CONTRAST` is rendered off-screen and cannot be tapped, so only 4 of the 5 documented theme modes are actually reachable.* **(4)** *In `NIGHT`/`AMOLED_BLACK` (and by the same code path, `HIGH_CONTRAST`), chapter headings styled by the EPUB's own CSS with an explicit dark color (this test book's `h1 { color: #333 }`) become low-contrast/near-invisible, because `buildThemeJs` only overrides `body { background-color; color }` — an explicit per-element color on a child element isn't touched by that override and doesn't inherit from `body`. Any real-world EPUB with its own explicit text colors will have the same problem in the dark themes.*
*None of these four are regressions from the two already-fixed blocking bugs — they're new findings from testing the full flow for the first time now that basic rendering works. The core parsing/rendering/reflow-reader-screen work is genuinely functional (Steps 1-4, 6, 7, 8 all passed); items 1 and 2 above are real functional gaps worth a fast follow-up before calling reading-progress UX complete, since "resume where you left off" is one of the plan's explicit requirements.*
